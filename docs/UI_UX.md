# Money Context UI / UX Specification

# 1. UX 목표

Money Context의 가장 중요한 UX 원칙은 다음이다.

> 기록은 10초 안에, 분석은 충분히 깊게.

사용자가 매번 상세 재정 폼을 채우게 하지 않는다. 일반 지출은 금액, 카테고리, 결제수단만으로 빠르게 끝날 수 있어야 한다.

# 2. 반응형 전략

## 모바일

주 역할: 빠른 기록, 현재 상태 확인.

Bottom Navigation:

```text
홈 | 내역 | + 입력 | 달력 | 더보기
```

`+ 입력`은 가장 눈에 띄는 Primary Action이다.

## 데스크톱

주 역할: 관리, 분석, 다건 조회/수정.

Sidebar:

```text
홈
거래내역
달력
자산
계획
통계
AI Export
설정
```

# 3. 홈

## Hero Summary

우선순위:

1. 다음 급여일까지 자유 사용 가능 금액
2. 하루 평균 사용 가능 금액
3. 이번 달 지출
4. 남은 예산

그 아래에:

- 이번 달 수입
- 저축률
- 순자산
- 카드 미결제

## Budget Risk

전체 카테고리를 길게 나열하지 않는다.

홈에서는 다음만 우선 노출한다.

- 80% 이상 사용
- 전월 대비 급증
- 예정 거래 포함 시 초과 예상

## Upcoming

- 카드 결제
- 반복 고정비
- 예정 지출
- 예정 수입
- 저축 적립

# 4. 빠른 거래 입력

## 4.1 기본 흐름

```text
거래 유형 선택
→ 금액 입력
→ 카테고리
→ 결제수단
→ 저장
```

기본 거래 유형은 마지막 선택을 기억할 수 있으나 사용자가 쉽게 변경할 수 있어야 한다.

## 4.2 추천

금액 입력 후 다음을 보여준다.

- 최근 사용 결제수단
- 자주 쓰는 카테고리
- 자주 쓰는 `카테고리 + 결제수단` 조합

추천은 단순 빈도와 recency 기반으로 구현하고 AI를 사용하지 않는다.

## 4.3 상세 옵션

Collapsed 영역:

- 날짜/시간
- 메모
- 태그
- 외화
- 할부

# 5. 이체 UX

이체는 지출 입력과 시각적으로 구분한다.

필수:

- 출금 계좌
- 입금 계좌
- 금액
- 날짜

같은 계좌 선택 불가.

# 6. 신용카드 UX

카드 상세 화면:

```text
이번 달 소비
총 미결제액
다음 결제 예정액
남은 한도
결제일
결제계좌
할부 잔여 스케줄
```

카드대금 납부를 사용자가 `지출`로 오해하지 않도록 `결제 처리` 또는 `카드대금 이체` 용어를 사용한다.

# 7. 거래 내역

## 모바일

날짜 그룹 리스트.

각 행:

```text
메모/대표명      -12,000
카테고리 · 결제수단
태그 (있으면)
```

## PC

Table column 권장:

```text
날짜 | 유형 | 내용 | 카테고리 | 결제수단 | 태그 | 원통화 | KRW | 상태
```

필터:

- 기간
- 유형
- 계좌/카드
- 카테고리
- 태그
- 상태
- 금액 범위
- 메모 검색

# 8. 자산

Summary:

```text
총 자산
총 부채
카드 미결제
순자산
```

그룹:

- 은행/현금
- 체크 결제수단
- 신용카드
- 일반 부채

`잔액 맞추기`는 계좌 상세에 둔다.

# 9. 계획

탭 또는 섹션:

```text
예산 | 저축 목표 | 미래 현금흐름
```

## 미래 현금흐름

확정 금액과 예정 금액을 시각적으로 구분한다.

예:

```text
현재 유동자산        1,200,000
카드 결제 예정        -184,000
고정비 예정           -129,000
저축 계획             -500,000
기타 예정 지출         -80,000
-------------------------------
자유 사용 가능         307,000
```

# 10. 통계

차트는 숫자를 대신하지 않는다. 차트 위/옆에 핵심 수치를 함께 표시한다.

지원:

- 월별 지출 추세
- 카테고리 비율
- 고정비/변동비
- 결제수단
- 태그
- 요일
- 주차
- 전월 대비
- 3/6개월
- 저축률
- 순자산

# 11. Export

화면 순서:

1. 분석 목적 선택
2. 기간 선택
3. 포함 데이터 확인
4. Preview
5. Markdown 복사 / JSON 다운로드 / CSV 다운로드

`GPT용 Markdown 복사`를 Primary Action으로 둔다.

# 12. Empty State

단순히 `데이터가 없습니다`라고 끝내지 않는다.

예:

```text
아직 거래가 없어요.
첫 지출을 기록하면 이번 달 예산과 소비 분석을 시작할 수 있어요.
[첫 거래 기록]
```

# 13. Error State

- 저장 실패 시 입력값을 유지한다.
- 네트워크 실패로 중복 저장되지 않도록 submit idempotency를 고려한다.
- 금융 계산 실패 시 0으로 조용히 대체하지 않는다. 데이터 계산 오류임을 표시한다.

# 14. 접근성

- 색상만으로 수입/지출/위험을 구분하지 않는다.
- 금액은 locale 기반 formatting.
- 폼 label 제공.
- keyboard navigation 지원.
- 차트에는 텍스트 요약 제공.

# 15. 디자인 톤

- 금융 앱처럼 신뢰감은 유지하되 은행 앱처럼 무겁지 않게.
- 한 화면에 모든 데이터를 밀어 넣지 않는다.
- 숫자 위계가 분명해야 한다.
- 경고 색상 남용 금지.
- 모바일에서 빠른 입력과 현재 상태 숫자가 가장 먼저 보여야 한다.

# 16. 달력

월간 그리드(6주 42칸)로 자신의 기록을 회고한다.

셀 표시:

- 날짜 숫자 (오늘은 필 배경, 이웃 달은 흐리게)
- 수입이 있는 날만 초록 윗줄 `+금액`
- 지출이 있는 날은 아랫줄 `-금액`
- 배경은 지출 강도 히트맵 0–4단계 (분위수 기준)
- 예정 항목이 있으면 점선 하단 보더와 건수

확정과 예정을 시각적으로 구분한다. 예정 거래, 카드 결제일, 반복 고정비는
표시만 하고 수입/지출 합계에는 넣지 않는다.

날짜를 선택하면 시트가 열리고 그날의 확정 거래와 예정 항목을 각각의
섹션으로 보여준다. `이 날짜로 기록` 버튼이 해당 날짜가 채워진 입력
화면으로 보낸다.

접근성: 그리드는 `role="grid"`이며 방향키로 이동하고 Enter로 상세를 연다.
각 셀의 `aria-label`이 날짜·수입·지출·예정 건수를 텍스트로 전달하므로
히트맵 색과 점선에만 의존하지 않는다.

URL은 `?ym=YYYY-MM`을 쓴다. 뒤로가기, 새로고침, 링크 공유가 모두 동작한다.
